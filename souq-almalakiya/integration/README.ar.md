# جوافة ← سوق الملكية: موصل جاهز للمراجعة، غير متصل إنتاجيًا

تاريخ: 22 نوفمبر 2026. **حالة تنفيذ الحي: BLOCKED**. لا تحتوي الحزمة على منتجات جوافة الحية ولا بيانات اعتماد أو بيانات مالية.

## ما تم التحقق منه
- MSSQLSERVER يعمل على JAWAFFASVR (فحص فعلي عبر SentinelX).
- حساب SentinelX الحالي هوية خدمة منخفضة الامتياز؛ قراءة ملف اعتماد user_read المشفر رفضت (Access denied).
- مستمع واجهة user_read القديمة على 127.0.0.1:3467 غير متاح حاليًا. مستمع 3456 القديم موجود على 127.0.0.2 وكان موثقًا تاريخيًا بحساب sa، وهو غير معتمد للمتجر.
- خريطة الجداول المرشحة سابقًا: dbo.Items.ItemCode/FamCode وdbo.Families.FamCode. حقول الرصيد القابل للبيع والفرع ووحدة القياس لم يتم اعتمادها من المصدر الحي.
- خيار الربط مع متجر في TrustSoft لم يُختبر ولا يجوز اعتباره مفعلًا. لا يُكتب أي صنف أو فاتورة أو كمية إلى Jawafa_DB.

## وظيفة catalog-contract.cjs
مكوّن تحويل PURE بلا أي اتصال SQL ولا تعديل سجلات؛ يقبل *فقط بعد تقديم أدلة مستقلة من واجهة خاصة مصادق عليها* لقطة كاملة من المصدر، ويطبق:
- `availablePieces >= 10` على الوحدة PIECE (حبة) فقط؛ يستثني الكميات الأقل والأصناف الموزونة التي لا تتطابق مع وحدة القطع.
- يبقي العائلات الأصلية حسب رموزها وأسمائها، ويرفض أي ربط ناقص أو رمز صنف مكرر.
- يمنع استخدام اللقطة الأقدم من 15 دقيقة، أو السعر غير المعتمد/الضريبة غير المعروفة، أو الكمية دون تدقيق المبيعات غير المرحلة.
- يرفض مصدرًا يعمل بحساب sa أو اتصال TLS غير موثوق أو صلاحيات DML غير مفحوصة.
- لا يفتح SQL من المتصفح ولا يحمل أسرارًا ولا ينسخ بيانات مستخدمين.

## متطلبات إغلاق الربط
1. تشغيل API محلية بداخل الخادم تحت هوية Windows مخصصة يمكنها قراءة ملف DPAPI وتثبت `ORIGINAL_LOGIN()='user_read'`، رفض DML وحصر الكائنات، TLS بسلسلة موثوقة.
2. دراسة `Items` و`Families`، ومصدر السعر وقيمة المخزون لكل فرع ووحدة وشروط البيع؛ التحقق من منع الخصم المزدوج للمبيعات غير المرحلة. اعتماد شاشة TrustSoft الأصلية واسم خيار «الربط على متجر» وآثاره.
3. API/بوابة HTTPS خاصة مع mTLS أو توقيع HMAC، مصدر يطابق الخادم المعتمد، تسلسل ومعرّف لقطة، واستيراد **إلى قاعدة المتجر المنفصلة فقط**.
4. مخزن كتالوج متزامن durable مع آلية وضع علامة على العناصر غير المتوفرة، اختبارات حدود 9/10/11، والفروع والوزن والضريبة ومطابقة عدد المنتجات.
5. اختبار متصفح E2E حقيقي لطلب تجريبي موثّق في قاعدة المتجر الخاصة، مع منع إنشاء قيد أو فاتورة في ERP دون تكامل كتابة معتمد وفصل تدقيق مستقل.

للاختبار المحلي: `node --test tests/catalog.test.cjs`.
**تحذير:** بيانات الاختبار تركيبية وليست أصناف جوافة.
