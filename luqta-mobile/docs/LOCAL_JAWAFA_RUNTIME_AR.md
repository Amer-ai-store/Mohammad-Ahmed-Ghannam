# لُقطة — تشغيل خادم التجارة الخاص محليًا (30 أكتوبر 2026)

### حالة الفحص الفعلية

- تم تشغيل Node 24 على `JAWAFFASVR` محليًا على `127.0.0.1:8790`.
- اختبار `GET /api/health`: HTTP 200.
- تسجيل دخول المدير: HTTP 200.
- `GET /api/admin/jawafa/source`: HTTP 200؛ مصدر `Jawafa_DB` وضع `FORENSIC-READ-ONLY`، فهرس 1,024 جدولًا.
- `GET /api/admin/jawafa/catalog-preview`: HTTP 200؛ معاينة 20 سجلًا.
- الوصول دون تسجيل دخول: HTTP 401.
- كتالوج المنتجات في بيئة الإنتاج: صفر منتجات تجريبية.
- خدمة محلية مع SQLite مستقلة في مساحة ملف المستخدم `%LOCALAPPDATA%\JawafaLuqtaCommerce`؛ بيانات اعتماد المدير أنشئت على الجهاز محليًا فقط ولم تُنقل إلى GitHub.
- سجّل مشغّل الخادم مهمة Windows `LuqtaCommerceOnLogon`، وهي **عند تسجيل الدخول فقط** ولا تضمن بدء الخدمة قبل تسجيل الدخول أو تعافيها بعد أعطال التشغيل.
- جميع الاختبارات السابقة للمسارات لا تثبت وصول الهاتف أو تكامل كميات البيع.

### طريقة التشغيل

شغّل `node luqta-mobile/server/start-jawafa-local.mjs` على Windows بعد تثبيت Node 24 من حساب Windows المخوّل. يربط الخدمة على `127.0.0.1:8790` فقط ولا يفتح منافذ الشبكة.
أول تشغيل ينشئ بيانات دخول خاصة في ملف محلي. تعامل معه كسر؛ لا ترفعه أو ترسله عبر الدردشة. ملف SQLite خاص بالتجارة، ولا يكتب أي شيء في `Jawafa_DB`.

### المانع الخارجي

GitHub Pages ليس خادم Node ولا قاعدة بيانات تشغيلية؛ الربط من الهاتف يحتاج بوابة HTTPS خاصة بمصادقة وحماية وأصل دائم. رفض Railway الخدمة لانتهاء التجربة. لا يجوز نشر الجسر المحلي `3456` أو جعل قاعدة SQL متاحة مباشرة. ينبغي تفعيل Cloudflare Tunnel **مُسمّى** مع نطاق يملكه المشروع أو استضافة HTTPS متكاملة بقاعدة دائمة. Quick Tunnel مؤقت للتجارب وغير مناسب لاستضافة الطلبات وبيانات العملاء إنتاجيًا.

### الكمية الفعلية

`quantityMappingVerified=false` و`saleableImportEnabled=false` حتى تعتمد شاشة TrustSoft الأصلية مصدرًا زمنيًا صحيحًا يشمل الفرع والوحدة وخصم المبيعات غير المرحلة مرة واحدة. الأصناف الموزونة ذات الكسور تحتاج نموذج كمية عشريًا ولا يجوز تقريبها.

### الاختبار المطلوب قبل اعتماد الهاتف

1. استضافة HTTPS آمنة موثقة مع مصادقة المدير ووصول فعلي من الهاتف.
2. ربط قاعدة المتجر الخاصة الدائمة + نسخ احتياطي مشفر واستعادة مثبتة.
3. واجهات إدخال/تعديل/إلغاء لكل شاشة وقيود الدور، ثم اختبار E2E حقيقي.
4. بعد اعتماد مصدر الكمية والعروض: اختبار مخزون صنف بفرعه ووحدته وتاريخ اللقطة قبل نشره للبيع.
