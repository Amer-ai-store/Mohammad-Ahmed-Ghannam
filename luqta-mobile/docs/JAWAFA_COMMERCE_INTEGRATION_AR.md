# ربط متجر لُقطة بمركز القيادة وجداول جوافة — عقد عمل 30/10/2026

## القرار المعتمد
تعليمات المالك المباشرة هي المصدر المعتمد عند تعارضها مع التقارير السابقة. الهدف إدارة المتجر من **لوحة القيادة المركزية** ومن **شاشة المدير داخل التطبيق**، وربط أصنافه وكمياته وعروضه بجوافة، دون كتابة أي بيانات في قاعدة Jawafa_DB أو كشف بيانات SQL للمتصفح.

## ما هو متوفر في الكود
- `dashboard/index.html` يحتوي قسم `data-view="luqta"`، ويحمّل `dashboard/luqta-api.js` و`dashboard/luqta-integration.js`. اتصال المدير يعتمد HTTPS وتسجيل دخول خادم التجارة، لا GitHub Pages كخادم بيانات.
- `luqta-mobile/server/commerce.mjs` خادم Node مع SQLite مستقلة للمتجر. يُخزن العملاء والطلبات والمخزون المستورد وخصومات المتجر. **GitHub مستودع شفرة وليس قاعدة بيانات تشغيلية**؛ لا ترفع SQLite أو سجلات العملاء أو مفاتيح الوصول إليه.
- تمت إضافة قسم العروض والتصميم إلى اللوحة المركزية وإدارة الهاتف. تصميم الواجهة الأولي يدعم اللون الرئيسي وعنوان الرئيسية ووصفها وإظهار المساعد؛ تعديل بنية الشاشات أو البرمجة يستلزم مراجعة وإصدار تطبيق جديد.
- أُضيف عقد `jawafa-inventory-v1` لمعاينة كمية جوافة الفعلية أو استيرادها إلى **قاعدة المتجر فقط**، ورفض اللقطات القديمة والتناقضات. لا يصل مباشرة بقاعدة SQL.

## مصدر المخزون المطلوب
**الكمية الجاهزة** قبل احتساب المبيعات غير المرحلة، و**الكمية الفعلية للبيع** = الجاهزة − المبيعات غير المرحلة، بشرط التأكد أن الكمية الجاهزة لم تخصم هذه المبيعات سابقًا. إذا كانت شاشة النظام تُرجع فعليًا رصيدًا بعد الخصم بالفعل فلا يُخصم مرة ثانية. يجب تدقيق دلالة الحقول مع تقرير أو شاشة TrustSoft الرسمية والفرع والوحدة قبل تفعيل مزامنة إنتاجية. أي تعارض يوقف الاستيراد ولا يُسقطه بصمت.

في فحص أسماء الجداول عبر الجسر المحلي بتاريخ 30 أكتوبر 2026 تم رصد أسماء جداول مرشحة للأصناف والكميات والعروض، لكن **لم تُعتمد خريطة SQL أو استعلام المخزون النهائي**. قد تكون بعض الجداول مرحلية أو للسندات، وليست مصدر الرصيد الحالي.

عقد HTTPS الخاص بمخزون جوافة (داخل جسر خاص مصادق عليه) يجب أن يعيد:
```json
{
  "schema": "jawafa-inventory-v1",
  "snapshotAt": "2026-10-30T18:00:00.000Z",
  "items": [
    {
      "id": "SKU_1",
      "sku": "SKU_1",
      "name": "اسم الصنف",
      "category": "اسم العائلة",
      "price": 1.5,
      "readyQuantity": 12,
      "unpostedSalesQuantity": 4,
      "actualQuantity": 8
    }
  ]
}
```
**الأرقام أعلاه أمثلة تعليمية وليست بيانات جوافة الحقيقية.** معرف الصنف ثابت، والكميات أعداد صحيحة لأن مخزون SQLite الحالي يستخدم INTEGER. الأصناف الموزونة والكسور (كيلوغرام) تحتاج تغيير نموذج وحدات قبل استيرادها، ولا يجوز تقريبها عشوائيًا. حد الاستيراد الحالي 2,000 صنف/دفعة، ولا يثبت اكتمال قاعدة الأصناف الأكبر.

العمليات:
- `POST /api/admin/inventory/jawafa-preview`: فحص ومعاينة بدون أي كتابة.
- `POST /api/admin/inventory/jawafa-import` مع `confirm:true`: استيراد محدود إلى SQLite الخاصة بالمتجر، مع سجل تدقيق وتراجع آمن وفق الشروط الحالية.
- `GET/PUT /api/admin/inventory/connector` و`POST /api/admin/inventory/sync`: موصل HTTPS قائم. إذا عاد المصدر بعقد جوافة، تُطبق المعادلة والتحقق قبل الاستيراد. لا تنشر الجسر المحلي 127.0.0.1 على الإنترنت؛ استعمل وسيط HTTPS خاصًا مع مصادقة وأقل صلاحيات.

## العروض والتصميم
- `GET /api/admin/offers` و`POST /api/admin/offers/import` مع تأكيد: مراجعة/تعديل أسعار العرض والسعر السابق للمنتجات الموجودة في SQLite فقط. ما زالت **مطابقة شاشة عروض TrustSoft** وتواريخ النفاذ والفرع والضرائب تحتاج عقد مصدر فعلي قبل الاستيراد الدوري.
- `PATCH /api/admin/settings` مع `storefront` يدعم `accentColor` بصيغة HEX، و`heroTitle` و`heroSubtitle` و`showAssistant`. `GET /api/settings` يتيح التطبيق قراءة إعداداته العامة. مصادقة المدير مطلوبة للتعديل.

## ما لم يثبت/ما يمنع قبول إنتاجي
1. لم يُنشر أو يُختبر خادم تجارة عام دائم مع قاعدة SQLite مستقرة، HTTPS، نسخ واستعادة آمنة، وربط المدير من الهاتف. مستودع GitHub/Pages وحده لا يشغّل API أو SQL.
2. لم يعتمد مصدر رسمي لأعمدة الكمية الجاهزة والفعلية والمبيعات غير المرحلة على مستوى الفرع/الوحدة والوقت؛ لا تعد أي مزامنة حية مكتملة قبل ذلك.
3. لم تربط شاشة العروض الحية لجوافة بالموصل ولم يُختبر عرض فعلي له تاريخ انتهاء.
4. لم تُختبر النسخة الجديدة على هاتف فعلي ولم تُبنَ حزمة APK جديدة بعد هذه التعديلات.
5. تعديلات الدردشة على الشفرة تُنفذ عبر GitHub بإذن مراجعة ونشر مستقلين. قناة مهام الوكلاء في التطبيق هي طابور طلبات وليست محركًا يطبق الشفرة تلقائيًا.

## اختيار قاعدة البيانات
**القرار المرحلي:** الاستمرار مؤقتًا في Node/SQLite القائمة مع تخزين دائم مشفر ونسخ خارج الموقع على خادم تجارة مستقل خلف HTTPS مع حماية المفاتيح. لا Firebase قديم كمصدر ثانٍ للمخزون ولا SQLite في GitHub. قبل الإنتاج نختبر القدرة على الاستضافة المستدامة أو نرحّل إلى PostgreSQL المدار عند الحاجة بعد اختبارات التوافق، دون تغيير مصدر الحقيقة في جوافة.

## قواعد القبول
- READ ONLY في Jawafa_DB؛ قاعدة المتجر فقط التي تقبل تغييرات المدير المصادق عليه.
- حسابات المالك والوكلاء وصلاحياتهم حسب أقل امتياز؛ أسرار خارج المستودع.
- لا تسمية `DONE` إلا مع دليل: اختبار تكامل خادم تجارة، اتصال جسر خاص، مطابقة وحدات وكمية الأصناف والفرع، عرض حقيقي، وتحديث ظاهر على الهاتف.
