# خارطة تنفيذ Amer AI Store

## ما أُضيف إلى النموذج الأولي

النسخة الحالية تنقل إدارة العمل من تخزين المتصفح إلى Worker وD1، مع API موحد، والتحقق من المدخلات، وإصدار حالة يمنع تعارض الكتابة، وتحديث الواجهة دوريًا، وسجل خوادم وفحوص صحة مقيدة بأصول مسموحة. أُضيفت متابعة مباشرة للمستودع المعتمد والتزاماته وفروعه وتشغيلات Actions، بذاكرة D1 مؤقتة وحالة قدم وأخطاء واضحة. API لقطة التطبيق وشاشتها متاحان، والعميل المحلي مسودة غير منشورة. نتائج الاختبارات والبناء والنشر المعتمدة توجد في [سجل التحقق](verification.md).

## الأعمال المتبقية

| الخطوة | العمل المطلوب | معيار الإنجاز |
| --- | --- | --- |
| توحيد هوية مصدر التطبيق | مطابقة مصدر النسخة المقصودة مع هوية وصور Luqta وجلب التغييرات غير المنشورة من جلسة Codex الأخرى. | تُحدد نسخة مرجعية واحدة وتُراجع فروقها مع مسودة الربط؛ لا تُنشر تعديلات في تطبيق مختلف. |
| تفعيل Android على جهاز | بناء النسخة المرجعية التي تتضمن عميل AAS وتثبيتها وتهيئة وصول المالك للموقع الخاص. | ينجح اختبار الصحة، ثم يظهر إيصال `app/sync` من الجهاز ويتطابق عدد سجلات Room مع لقطة D1. |
| تحقق البناء في GitHub | تشغيل workflow الموجود فعلًا بعد اعتماد المصدر وأذون النشر اللازمة. | يظهر تشغيل مرتبط بـSHA معروف ونتيجة من Actions نفسها؛ غياب التشغيل يبقى حالة بلا نتيجة بناء. |
| ربط مصدر المتجر | تحديد نظام المنتجات والطلبات الرسمي، ثم إضافة محول أو webhooks، وصلاحيات وعمليات دمج بدل لقطة جهاز واحد. | يظهر منتج أو طلب من المصدر الحقيقي، ويُختبر تحديث مأذون ويظهر أثره فيه. |
| مقارنة وأسواق خارجية | توصيل مزود بيانات حقيقي للرادار والمقارنة والبيانات الاجتماعية. | تعرض نتائج لها مصدر وتوقيت، ويظل الفشل ظاهرًا عند غياب البيانات. |
| تهيئة Gemini | توفير مفتاح مزود وموديل مسموح في إعدادات Worker وتفعيل محول `ai/generate`. | ينجح طلب نص وصورة ويُتحقق من الرد الفعلي؛ يظل المفتاح خارج Android وتظهر أخطاء المزود بوضوح. |
| هوية وأدوار مستقلة | إضافة مستخدمين وأدوار تطبيقية إذا احتاج الفريق مستويات وصول مختلفة. | تفشل الكتابة غير المسموحة حتى عند استدعاء API مباشرة. |
| تشغيل الوكلاء | إضافة طابور وعامل تنفيذ ونتائج وتكاليف من المزود، فوق محول النموذج عند الطلب. | تُنفذ مهمة محددة، وتظهر نتيجتها الحقيقية أو سبب فشلها، دون مؤشرات تقديرية على أنها فعلية. |
| موافقات التنفيذ | ربط القرار بإجراء خارجي محدد ومدخلاته وصلاحيته ومفتاح عدم تكرار. | يظل الإجراء الخارجي متوقفًا حتى الموافقة الصحيحة؛ الرفض أو انتهاء الطلب يمنعانه. |
| تشغيل الفريق | نسخ احتياطية واستعادة، ورصد الأخطاء، وسياسة احتفاظ وحدود الاستخدام. | تُختبر استعادة البيانات، ويُرصد فشل اتصال، وتُراجع الرحلات الأساسية من أجهزة مختلفة. |

المستودع مرتبط للمتابعة والقراءة فقط؛ لا يعني ذلك رفع مسودة Android أو إنشاء PR أو بناء APK. مصدر Android الذي توفر هنا هو المستودع المنشور، وليس حالة جلسة Codex الأخرى غير المنشورة. الخوادم الأخرى لم تُحدد بعناوين أو مصادر؛ لا يمكن إعلان تعديل API لها قبل الوصول إلى المصدر وتشغيل اختبار عليها. نجاح بناء الكود أو فحص API لا يثبت أن جهاز المستخدم قد رُبط أو أن مبيعاته تحققت.
