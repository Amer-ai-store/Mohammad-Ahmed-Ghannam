# ربط المستودع والتطبيق والخوادم

## الربط المنجز

المصدر المعتمد هو [Mohammadzxzx1991/Mohammad-Ahmed-Ghannam](https://github.com/Mohammadzxzx1991/Mohammad-Ahmed-Ghannam)، الذي حدده المستخدم. شاشة «مستودع GitHub» تقرأ منه مباشرةً بيانات المشروع والفرع الافتراضي وأحدث الالتزامات والفروع وتشغيلات GitHub Actions، مع روابط المصدر وتوقيت الفحص. الربط للقراءة والمتابعة؛ لا يرفع ملفات أو ينشئ PR أو يشغل بناءً.

يعرض `GET /api/v1/github` أحدث لقطة صالحة من GitHub أو ذاكرة D1 المؤقتة لخمس دقائق. زر التحديث يستدعي `POST /api/v1/github/refresh`، مع فاصل دقيقة بين المحاولات واحترام حد طلبات GitHub. إذا فشل الجلب، تبقى اللقطة السابقة ظاهرة بعلامة قدم وخطأ؛ وإذا تعذرت قراءة Actions، لا تُعرض نتيجة بناء مفترضة. تشغيلات Actions الفارغة تعني عدم وجود تشغيلات أعادها API، ولا تعني نجاح البناء.

المستودع العام لا يحتاج رمزًا للقراءة. `GITHUB_TOKEN` اختياري، ويهيأ في بيئة Worker فقط عند الحاجة. لا تضعه في مصدر الواجهة أو ملفات المشروع أو نسخ الحالة.

## حالة التطبيق المثبت

متابعة المصدر في GitHub منفصلة عن اتصال جهاز المستخدم. «بيانات التطبيق» لا تعرض منتجات أو طلبات حتى يستقبل Worker لقطة خدمة موثقة عبر `POST /api/v1/app/sync`. مصدر GitHub أو نجاح فحص صحة خادم لا ينشئ هذا الإيصال.

نسخة المصدر المحلية في `/workspace/apps/mohammad-ahmed-ghannam` من الالتزام `aa1db27385700f30773db27d81898741ad698a04`، ومسودة الربط في الفرع `aas/live-command-center`. المصدر المنشور Android/Kotlin مع Jetpack Compose وRoom. مسودة عميل AAS والتغييرات المحلية لم تُنشر، بسبب اختلاف هوية وصور تطبيق Luqta عن المصدر المنشور الذي جرى فحصه. لم يُعلن إنشاء PR أو رفع APK أو اتصال جهاز.

معرف جلسة Codex `01a13140-17e0-7168-9a28-f71e37190060` لا يتيح قراءة تعديلات تلك الجلسة غير المنشورة. يلزم توحيد مصدر النسخة المقصودة قبل بناء مسودة الربط ونشرها. راجع [سجل التحقق](verification.md) للنتائج المنجزة فعلًا.

## إعداد جهاز يتضمن عميل AAS

الخطوات التالية تخص نسخة تطبيق تحتوي بالفعل شاشة إعداد مركز القيادة؛ ليست وصفًا لميزة منشورة في المستودع الحالي:

1. بعد توحيد المصدر، ابنِ النسخة التي تتضمن عميل AAS وثبتها على جهاز المالك.
2. افتح «ربط مركز القيادة AAS-CC» فيها. عنوان الموقع هو أصل HTTPS دون `/api/v1` أو بيانات دخول أو معاملات؛ الافتراضي `https://amer-ai-command-center.eagerlark64.chatgpt.site/`.
3. نزّل ملف اتصال المالك من شاشة «الخوادم والربط» في لوحة الموقع الخاص، واستورده في إعداد التطبيق. الملف يحتوي وصول الخدمة والموقع الخاص؛ احذفه بعد الاستيراد ولا تشاركه. يبقى خيار المزامنة التلقائية معطلًا إلى أن يختاره المالك.
4. اختبر الوصول. يلزم رد JSON بعقد `status: ok` و`storage: D1`؛ تنزيل الملف أو استيراده أو فحص الصحة لا يرسل منتجات وطلبات.
5. أرسل المزامنة صراحةً، ثم تحقق من إيصال الخادم ووقت الاستلام والمراجعة وعدد السجلات، ومن ظهورها في «بيانات التطبيق» باللوحة.

المصادقة تستخدم `X-AAS-API-Key`، ويحتاج الموقع الخاص أيضًا `OAI-Sites-Authorization`. الأسرار تهيأ في Worker. تصميم المسودة يحفظ وصول الجهاز مشفرًا باستخدام AES-GCM ومفتاح Android Keystore، ويستثنيه من النسخ الاحتياطي؛ لا يُضمن في المصدر أو APK. المزامنة التلقائية، إن اختارها المالك، مرتبطة بفتح التطبيق وليست خدمة خلفية مستقلة. هذه القدرات تحتاج تحققًا على النسخة المرجعية المثبتة قبل اعتبارها متصلة.

## معنى لقطة التطبيق

اللقطة تمثل سجلات التطبيق المحلية كما هي، وقد تتضمن منتجات تجريبية قديمة في قاعدة المستخدم. يستقبل الخادم الحقول المسموحة للمنتجات والطلبات فقط، ويستبعد بيانات العملاء والعناوين والبطاقات والدفع، ويحدد وقت الاستلام من الخادم. كل لقطة تحل محل السابقة، ولا تدمج بيانات عدة أجهزة.

لا يثبت قبول اللقطة تحصيل دفعات أو اعتماد المخزون في نظام متجر مستقل. مصادقة ChatGPT الخاصة بواجهة المتصفح لا تجيز صناعة لقطة تطبيق؛ `app/sync` يتطلب مصادقة الخدمة. الاستيراد وإعادة ضبط العمل يحافظان على آخر لقطة مستلمة.

`GET /api/v1/products/search` يقرأ كتالوج اللقطة فقط. المقارنة عبر `GET /api/v1/products/:id/compare` تعيد سعر المنتج المسجل فيها؛ الرادار والمقارنة الخارجية والبيانات الاجتماعية تعيد `503 integration_not_configured` حتى توفير مصدر حقيقي.

## نقل العمل من النسخة المحلية القديمة

عند فتح الموقع من المتصفح والأصل نفسيهما، يبحث مساعد النقل عن `aas-command-center.state.v1` ويحتفظ به دون تغيير. إذا كانت قاعدة v2 جديدة في المراجعة `0`، ينقل المساحات والمهام والملاحظات المضافة يدويًا، والموافقات المرتبطة بتلك المهام، بعد التحقق من صلاحيتها. لا ينقل مهام أو نشاط العرض الأولي ولا يمنحها صفة بيانات فعلية.

وجود عمل محفوظ على الخادم أو تعارض مراجعة يمنع النقل التلقائي؛ النسخة المحلية تبقى محفوظة للمراجعة. هذا مسار تحويل خاص، ولا يجعل الاستيراد المباشر لملف العرض v1 مقبولًا في API الحي.

## سجل الخوادم الخارجية

من «الخوادم والربط»، أضف `name`, `baseUrl`, `apiPrefix`, `healthPath` واسم متغير سر `tokenEnv` إن احتاج الخادم. اسم المتغير ليس قيمة المفتاح ولا يهيئها تلقائيًا. العنوان HTTPS باستخدام اسم نطاق، والمسارات نسبية تبدأ بـ `/`.

يهيئ مسؤول Worker أصل النطاق في `AAS_ALLOWED_SERVER_ORIGINS` كمصفوفة JSON، مثل `["https://api.example.com"]`، بعد مراجعة ملكيته ووجهته. الأصل لا يشمل مسار API. عند وجود `tokenEnv` يرسل Worker السر المقابل كـ `Authorization: Bearer …` إلى مسار الصحة.

فحص الاتصال طلب HTTP فعلي بمهلة ثماني ثوانٍ، دون اتباع إعادة توجيه. رفض الأصل أو غياب السر يمنع بدء الفحص. نجاح الصحة لا يثبت توافق المنتجات والطلبات أو تعديل مصدر ذلك الخادم. تعديل `apiPrefix` في السجل يغير إعداد الاتصال هنا؛ تعديل API في خادم خارجي يحتاج عنوانه ومصدره وصلاحية تعديله ثم اختباره عليه.

## توليد النص وتحليل الصور

`POST /api/v1/ai/generate` يوفر محول Gemini خادميًا للنص والصورة، ويحتاج `GEMINI_API_KEY` و`GEMINI_MODEL` أو `GEMINI_ALLOWED_MODELS` في بيئة Worker. المفتاح لا يدخل العميل. عند غياب المزود يعيد `503 provider_not_configured` دون نتيجة افتراضية.

توجيه `ModelService` إلى هذا المسار جزء من المسودة المحلية غير المنشورة، ويحتاج توحيد المصدر وبناء النسخة قبل اعتباره ميزة في تطبيق المستخدم. لا يوجد تشغيل مستقل للوكلاء، وقبول موافقة في لوحة العمل لا يشغل نموذجًا أو إجراء متجر تلقائيًا.
