# دليل الكود الكامل للوحة AAS-CC وبيئات AAS-AW

هذا الدليل مرافق لمصدر **Amer AI Store Command Center**. يحتوي أرشيف المصدر على الواجهة العربية، وWorker للخادم، ومخطط D1 وترحيلاته، والاختبارات، وحزم التكامل المصدرية. تُحفظ بيانات العمل الفعلية وإعدادات المزوّد في قاعدة الموقع وبيئته؛ لا تُنسخ داخل الأرشيف.

رابط اللوحة الحالية: https://amer-ai-command-center.eagerlark64.chatgpt.site/

رابط المستشار والمحادثة: https://amer-ai-command-center.eagerlark64.chatgpt.site/#advisor

## 1. التشغيل على جهازك

ثبّت **Node.js 24.5 أو أحدث**، ثم فك الأرشيف وافتح الطرفية داخل مجلد `amer-ai-command-center`:

```bash
npm ci
npm run dev
```

افتح `http://127.0.0.1:3001`. يشغّل الأمر Worker وD1 محليين، ويطبق الترحيلات غير المطبقة، ويحفظ قاعدة التطوير في `.aas-local/d1`. بيانات التطوير مستقلة عن قاعدة الموقع المنشور.

المنفذ `3001` يضيف هوية مالك اختبارية على عنوان loopback فقط. المنفذ `3000` هو Worker المباشر ويتطلب مصادقة. لا تنشر خادم التطوير بوصفه نظام حسابات للإنتاج. أوقفه بواسطة `Ctrl+C`.

للفحص والبناء:

```bash
npm run check
npm test
npm run build
```

يشغّل `npm test` البناء تلقائيًا أولًا. لا يلزم تشغيل البناء منفصلًا قبل كل اختبار. ناتج البناء الرئيس هو `dist/server/index.js`، ويولّد أيضًا بيانات الاستضافة وحزم المنفّذ وجسر قاعدة البيانات. الملفات المولدة تعاد من المصدر، ولذلك لا يلزم تضمين `node_modules` أو Worker المبني في أرشيف المصدر.

ملف `.env.example` يشرح أسماء الإعدادات، وقيمه فارغة. **لا يقرأ خادم التطوير الحالي ملف `.env` تلقائيًا**؛ ينشئ `scripts/dev-server.mjs` bindings محلية محدودة. لتجربة مزوّد محلي، مرّر الإعدادات صراحة إلى Miniflare في بيئة تطوير منفصلة. في الاستضافة اضبطها عبر بيئة Sites. لا تجعل `.env` أو ملف اتصال يحوي رموزًا جزءًا من المصدر.

## 2. بنية التطبيق ومسار البيانات

```text
متصفح المالك: واجهة عربية + توجيه بالـ hash + الوضع الليلي
    |
    v
dist/api-store.js: طلبات API + مراجعة الحالة + تحديث دوري
    |
    v
server/worker.mjs: مصادقة + تحقق من الطلب + توجيه
    |                         |
    v                         v
D1: حالة وسجلات مشتركة       Gemini / GitHub عبر طلبات خادمية محددة
    ^
    |
منفّذ أو جسر محلي اختياري باتصال صادر مصادق عليه
```

الواجهة مكتوبة بوحدات JavaScript وHTML وCSS دون React. الخادم يستخدم نموذج `Request` و`Response` الخاص بـCloudflare Worker، وتُحزم وحداته بواسطة esbuild. مخطط SQLite/D1 موصوف باستخدام Drizzle.

## 4. الشاشات والقدرات

- مركز القيادة: حالة مشتقة من المهام والموافقات والنشاط المحفوظ، دون اختلاق مبيعات أو تشغيلات.
- مساحات AAS-AW: تجميع الوكلاء والمهام والملاحظات حسب مجال العمل.
- المهام والموافقات: إنشاء وتعديل وحفظ، واعتماد صريح للتغييرات التي تتطلب مراجعة.
- خريطة التنظيم: تسعة ملفات تعريف تنظيمية، مع أولويات واعتماديات وملكية موارد؛ المسار المتعارض ينتظر بينما يستمر المستقل.
- مراحل التنفيذ: تحليل ثم تعديل أو إضافة ثم تحقق؛ لا تنتقل البوابة دون الأدلة المطلوبة والمراجعة الحالية.
- المستشار: توصيات محلية محسوبة، ومحادثة Gemini عند توفر إعداد صالح وحصة وصلاحيات لدى المزوّد.
- المستودع: متابعة `Mohammadzxzx1991/Mohammad-Ahmed-Ghannam` وحالة المصدر وActions عند إتاحتها.
- بيانات التطبيق: تعرض اللقطات المستلمة فعلًا من تطبيق مصادق عليه.
- قاعدة البيانات: تعريف جسر SQLite ومراقبة لقطاته وعملياته وإيصالاته.
- الإعدادات والخوادم: حفظ إعدادات المؤسسة وتعريفات API وفحوص الصحة المسموح بها.
- المظهر: فاتح وداكن وتلقائي حسب النظام، مع تصميم RTL متجاوب.

الملفات التسعة ليست تسعة نماذج تعمل باستقلالية. المحادثة لا تعدّل ملفات الكود أو تنفذ أوامر أو SQL تلقائيًا؛ مقترحاتها الإدارية تحتاج اعتمادًا صريحًا. المنفّذ الاختياري يطبق رقعًا يراجعها المشغّل ويعيد أدلة اختبار، ويتطلب تشغيله خارج اللوحة.

## 5. قاعدة البيانات والتزامن

| الجدول | المحتوى |
| --- | --- |
| `aas_app_state` | وثيقة المؤسسة، `revision`، ووقت التحديث. |
| `aas_repository_cache` | لقطة GitHub وأوقات القراءة والمحاولة والخطأ. |
| `aas_control_records` | إعداد Gemini المشفر، المحادثات والمقترحات، وصلات البيانات وطوابيرها. |

للتعديل، يرسل العميل `expectedRevision` من آخر قراءة. يكتب الخادم إذا كان الإصدار ما زال مطابقًا. عند تغيره يرجع `409 revision_conflict`؛ تحدّث الواجهة الحالة ولا تعيد العملية تلقائيًا. القراءة الدورية تستخدم ETag لتقليل نقل البيانات.

لا تعدّل ترحيلًا مطبقًا؛ بعد تعديل `db/schema.ts` استخدم `npm run db:generate` وراجع الترحيل الجديد. أرشيف المصدر لا يحتوي قاعدة الإنتاج أو محادثاتها أو مفاتيحها المشفرة.

## 6. ربط Gemini ومعالجة أخطاء المحادثة

1. افتح المستشار ثم «فحص وربط Gemini».
2. أدخل قيمة مفتاحك في حقل المفتاح، أو استخدم المفتاح المحفوظ.
3. اجلب قائمة النماذج الفعلية من المزوّد. اسم اعتماد مثل `Gemini-API-2` ليس اسم نموذج.
4. اختر نموذج محادثة يدعم توليد النص وJSON، ثم احفظ.
5. جرّب رسالة قصيرة. جلب قائمة النماذج وحفظ الاختيار لا يثبتان توفر حصة توليد.

تُحفظ قيمة الاعتماد باستخدام AES-256-GCM ومفتاح خادم مستقل. جلسة اختيار النموذج صالحة عشر دقائق، ولا تستبدل الإعداد النشط حتى نجاح الحفظ. لا يعيد API المفتاح ولا يضعه في سجل المحادثة.

تطلب المحادثة الآن `responseMimeType: application/json` من Gemini. تقبل ردًا بالشكل التالي دون إنشاء إجراء:

```json
{"assistantMessage":"أستطيع مراجعة حالة المهام الحالية.","proposals":[]}
```

يجوز غياب `proposals` في الرد الاستشاري فتُعامل كقائمة فارغة. إذا أرسل النموذج مقترحات، تبقى العمليات والحقول والمعرفات خاضعة للتحقق؛ لا يتحول نص غير صالح إلى إجراء تلقائي.

| الكود | المعنى والإجراء التالي |
| --- | --- |
| `provider_not_configured` | لا يوجد إعداد قابل للاستخدام؛ راجع ربط المزوّد. |
| `provider_quota_exceeded` | حد معدل أو حصة عند المزوّد؛ راجع الحصة والفوترة وانتظر قبل المحاولة. |
| `provider_access_denied` | صلاحيات أو قيود وصول؛ راجع المفتاح والمشروع والخدمة. |
| `provider_model_unavailable` | النموذج غير متاح للطلب؛ أعد جلب القائمة واختر نموذجًا متاحًا. |
| `provider_request_invalid` | رفض إعدادات الطلب؛ راجع الاعتماد ودعم النموذج لصيغة JSON. |
| `provider_timeout` | لم يصل الرد قبل المهلة. |
| `model_no_result` | رد فارغ أو محجوب أو غير مكتمل؛ لا يُعرض كاستجابة ناجحة. |
| `assistant_invalid_response` | وصل نص لا يطابق صيغة المحادثة. |
| `assistant_invalid_proposal` | المقترح غير مسموح أو غير قابل للتحقق؛ لا يُطبّق. |

تظهر رسائل الخطأ المنقّاة داخل سجل المحادثة مباشرة. لا تعرض اللوحة نص خطأ المزوّد الخام أو أسراره، ولا تدّعي توليد رد عندما تكون النتيجة توصيات محلية.

## 7. أهم مسارات API

الأساس `/api/v1`، والوصول يتطلب هوية أو اعتمادًا حسب المسار. العقد التفصيلي وأجسام الطلبات في `docs/api.md`.

| المسار | الغرض |
| --- | --- |
| `GET /state` | قراءة حالة المؤسسة وإصدارها. |
| `/tasks` و`/workspaces` | إدارة المهام والمساحات وفق الطرق المحددة في عقد API. |
| `GET /coordination` | الهيكل والمسارات وحالة الاعتماديات المشتقة. |
| `GET /assistant/capabilities` | حالة إعداد المزوّد دون المفتاح. |
| `POST /assistant/provider/models` | اكتشاف النماذج بجلسة المالك. |
| `POST /assistant/provider` | حفظ الاختيار بعد التحقق. |
| `POST /assistant/chat` | طلب استشارة وحفظها دون تطبيق مقترحاتها. |
| `GET /assistant/history` | سجل المحادثة المنقّى. |
| `POST /assistant/apply` | اعتماد مقترح موجود على مراجعة الحالة المطابقة. |
| `POST /ai/generate` | توليد نص أو تحليل صورة؛ مستقل عن مقترحات المحادثة. |
| `GET /github` | آخر قراءة متاحة للمستودع مع المصدر والوقت والقيود. |
| `POST /app/sync` | استقبال لقطة التطبيق باستخدام مصادقة الخدمة. |
| `/database` و`/bridge/*` | إدارة الجسر واستقبال لقطاته وإيصالاته بصلاحيات منفصلة. |
| `/runner/*` | سياق التنفيذ وإيصالاته وتقدمه بصلاحيات المنفّذ المحدودة. |

مثال قراءة من داخل جلسة متصفح اللوحة نفسها:

```js
const response = await fetch('/api/v1/state', { credentials: 'same-origin' });
if (!response.ok) throw new Error('تعذرت قراءة الحالة');
const { state, revision } = await response.json();
console.log({ revision, tasks: state.tasks.length, workspaces: state.workspaces.length });
```

## 8. إعدادات الاستضافة

تُضبط القيم في بيئة الخادم، ولا تُكتب في ملفات الواجهة. هذه أسماء الإعدادات فقط:

| الاسم | الاستخدام |
| --- | --- |
| `DB` | ربط قاعدة D1. |
| `AAS_API_TOKEN` | اعتماد تطبيق أو خدمة خارجية. |
| `AAS_RUNNER_TOKEN` | اعتماد مستقل للمنفّذ والجسر. |
| `AAS_SECRET_ENCRYPTION_KEY` | مفتاح تشفير قيم Gemini المحفوظة؛ 64 خانة hexadecimal. |
| `AAS_ALLOWED_SERVER_ORIGINS` | مصفوفة JSON لأصول HTTPS المسموح بفحصها. |
| `AAS_PRIVATE_SITE_BEARER` | وصول الخدمة إلى بوابة الموقع الخاص عند تهيئته. |
| `AAS_PUBLIC_ORIGIN` | أصل الموقع المنشور. |
| `GEMINI_API_KEY` و`GEMINI_MODEL` و`GEMINI_ALLOWED_MODELS` | إعداد مزوّد عبر البيئة عند عدم وجود سجل إعداد مشفر. |
| `GITHUB_TOKEN` | اختياري لقراءة GitHub ضمن صلاحياته وحدوده. |

احتفظ بمفتاح التشفير القائم عند تحديث الموقع؛ تبديله دون إعادة تهيئة الاعتمادات يجعل السجلات القديمة غير قابلة للفك. إعدادات البيئة ليست ضمن أرشيف المصدر.

## 9. النشر وحدود التكامل

ملف `.openai/hosting.json` يعود إلى موقعك الحالي. أعد استخدام هويته عند تحديث الموقع نفسه. إنشاء موقع مستقل يحتاج تسجيل مشروع منفصل والحصول على هويته من المنصة. لا تنقل بيانات الاعتماد من ملفات اتصال إلى Git.

بعد فحص المصدر وبنائه، يمكن إنشاء حزمة نشر:

```bash
npm run package:site -- /absolute/path/aas-cc-site.tar.gz
```

هذه حزمة تشغيل مبنية، وتختلف عن ZIP المصدر الكامل. يتطلب النشر الفعلي رفع مراجعة المصدر المطابقة، ثم حفظ إصدار ونشره عبر Sites. أبقِ الوصول الخاص للموقع الحالي ما لم تغيّر مشاركته صراحة.

الخادم `192.168.1.99` عنوان داخل شبكة محلية؛ تنزيل الكود لا يوصله بالسحابة. يحتاج جسرًا يعمل داخل الشبكة باتصال صادر. المحوّل الموجود يدعم SQLite؛ لا يفترض نوع قاعدة المستخدم. كما أن متابعة GitHub لا تثبت اتصال تطبيق Android المثبت أو نجاح دفع أو شحن. خطوات التفعيل في `docs/database-bridge.md` و`docs/runner-setup.md` و`docs/integration.md`.
