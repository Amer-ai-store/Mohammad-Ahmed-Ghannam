# Amer AI Store — مركز القيادة ومساحات العمل

واجهة عربية لمتجر إلكتروني للمنتجات، تجمع **Amer AI Store Command Center [AAS-CC]** و**Amer AI Store Agent Workspaces [AAS-AW]** في تطبيق واحد. الواجهة تتصل بخادم API وقاعدة Cloudflare D1؛ إنشاء المهام والمساحات والملاحظات، وقرارات الموافقة، وإعدادات المؤسسة والخوادم تُحفظ في الخادم وتُعرض للمستخدمين الذين لديهم وصول إلى الموقع الخاص.

لشرح الملفات والكود ومسار البيانات وإعدادات التشغيل والأخطاء، راجع [دليل الكود الكامل بالعربية](docs/source-guide-ar.md).

أضيف نقل العميل ومصدر الخادم إلى [لوحة القيادة المعتمدة](https://amer-ai-store.github.io/Mohammad-Ahmed-Ghannam/#aas-overview). راجع [دليل الدمج والاتصال](docs/approved-dashboard.md) لفتح جلسة المالك والوصول إلى جميع شاشات AAS مع الإبقاء على قاعدة D1 الخاصة.

## التشغيل المحلي

يتطلب المشروع Node.js 24.5 أو أحدث، بما يدعم `--use-env-proxy` عند احتياج بيئة التطوير إلى وكيل الشبكة. من مجلد المشروع:

```bash
npm install
npm run dev
```

خادم التطوير يشغّل Worker مع قاعدة D1 محلية؛ لا تعتمد الواجهة على `localStorage` لحفظ بيانات العمل. تحفظ البيئة المحلية بيانات منفصلة عن قاعدة الموقع المنشور. راجع إعدادات التشغيل في `package.json` وملفات `scripts/` قبل تغيير المنفذ أو التخزين.

افتح `http://127.0.0.1:3001`. هذا منفذ معاينة محلي بهوية تطوير؛ منفذ Worker المباشر `3000` يحتاج مصادقة خدمة. لا تستخدم هوية التطوير في الاستضافة العامة.

```bash
npm run check
npm run build
npm test
```

البناء يولد Worker وملفاته وترحيلات D1 اللازمة؛ أعده بعد تعديل الواجهة أو الخادم وقبل اختبارات API. `npm run db:generate` يولد ترحيلًا عند تعديل مخطط قاعدة البيانات. نتائج التحقق الفعلية موثقة في [سجل التحقق](docs/verification.md).

لتجهيز حزمة نشر من بناء المصدر نفسه، استخدم `npm run package:site -- /absolute/path/site.tar.gz`. تتحقق أداة الحزم من تطابق تعريف الاستضافة وترحيلات البناء، وتضم Worker وبيانات الاستضافة ومجلد Drizzle المولّد دون قاعدة التطوير أو الأسرار. نشر Sites يطبق الترحيلات؛ لا تنشئ مسارات API الجداول أثناء الطلبات.

فحص المتصفح اختياري ويحتاج Playwright وChromium محليًا. عيّن `AAS_PLAYWRIGHT_MODULE` إلى المسار المطلق لملف `playwright/index.mjs` و`AAS_CHROMIUM_PATH` عند استخدام Chromium خارج المسار الافتراضي، ثم شغّل `node scripts/browser-live-qa.mjs` بينما خادم التطوير يعمل. هذا الفحص يُجري تغييرات اختبارية ويقبل عنوان تطوير محليًا فقط.

## ما يعمل في هذه النسخة

- **فريق من تسعة وكلاء:** منسّق، منتجات، تسويق، خدمة عملاء، تحليلات، عمليات، هندسة برمجيات، جودة وأمان، ومعرفة وأتمتة. الترقية تحافظ على تعديلات الفريق والمهام الحالية، وتضيف مساحة تقنية مستقلة مرة واحدة.
- **الخريطة التنظيمية والحية:** هيكل الإدارة، وملكية المهام، والاعتماديات، وانتظار الموارد، وأولوية الطابور مشتقة من الحالة المحفوظة. تعارض مورد يمنع البدء المتعارض في مساره فقط؛ تبقى المسارات الأخرى متاحة.
- **المستشار والمحادثة:** توصيات محلية قابلة للمراجعة ومحادثة Gemini عند ربط المزوّد. مقترحات النموذج تحفظ على الخادم وتحتاج اعتمادًا صريحًا على مراجعة المشروع الحالية، دون إعادة تنفيذ المقترح عند تكرار الضغط. تُحفظ مفاتيح المزوّد مشفرة، ولا تدخل سياق النموذج أو تخزين المتصفح.
- **قاعدة البيانات المحلية:** جسر SQLite باتصال صادر، ومخطط وعيّنات محددة محليًا، وطابور عمليات منظمة مع نسخ احتياطية وإيصالات فعلية. لا يوجد اتصال مثبت بالخادم المحلي قبل تشغيل الجسر عليه. راجع [دليل قاعدة البيانات](docs/database-bridge.md).
- **الوضع الليلي:** فاتح أو داكن أو بحسب النظام، مع حفظ تفضيل الجهاز وتحديثه بين علامات التبويب دون فقد مسودات النماذج.
- **مراحل التنفيذ:** خطط محفوظة في D1 بخطوات مرتبة: تحليل، تعديل أو إضافة، ثم تحقق. لا تُفتح الخطوة التالية قبل اكتمال الأدلة ونجاح جميع الفحوص على مراجعة المصدر الحالية. التعديل الجديد يبطل نتائج الخطوة وما بعدها، مع الاحتفاظ بسجل الأحداث. يتم تمييز التوثيق اليدوي عن تحليل الخادم وإيصالات المنفّذ.
- **تحليل المصدر:** فحص فعلي لأرشيف GitHub عند SHA مرصود، يشمل جميع الملفات النصية المؤهلة ضمن حدود الحجم. يحفظ بصمات الملفات والملاحظات ونطاق التغطية؛ لا يشغّل الكود ولا يدّعي نجاح بناء أو اختبار.
- **مركز القيادة:** مؤشرات مشتقة من المهام والموافقات والحالة المسجلة، وسجل نشاط ناتج عن التغييرات الفعلية.
- **مساحات العمل:** إنشاء وتعديل وحذف مساحات، وربطها بملفات الوكلاء، وإدارة ملاحظاتها ومهامها.
- **المهام والموافقات:** حفظ على الخادم، وتحديث الحالات، وقبول أو رفض طلبات المراجعة مع سجل تغيير. قرار الموافقة لا ينفّذ إجراءً في متجر خارجي.
- **إعدادات المؤسسة:** حفظ اسم المتجر وإعداداته في قاعدة البيانات المشتركة.
- **الخوادم:** تسجيل عنوان HTTPS ومسارات API والصحة واسم متغير سر اختياري؛ فحص الاتصال ينفّذ طلب HTTP من الخادم بعد السماح بالأصل في إعدادات الخادم.
- **التصدير والاستيراد:** تصدير حالة الخادم إلى JSON، والتحقق من نسخة الاستيراد قبل استبدال الحالة المشتركة. الاستيراد يؤثر في البيانات التي يراها جميع مستخدمي الموقع.
- **المزامنة:** تحديث كل ثلاث ثوانٍ باستخدام إصدار الحالة وETag، وإظهار حالة الاتصال. يرفض الخادم الكتابة على إصدار قديم لتجنب الكتابة فوق تعديل آخر.
- **بيانات التطبيق:** شاشة للكتالوج والطلبات التي يُبلغ عنها تطبيق Android، مع وقت استلام وإصدار الجهاز. لا تعرض بيانات متجر قبل استلام لقطة مصادق عليها، ولا تعتبر الطلبات دليلًا على تحصيل الدفعات.
- **مستودع GitHub:** قراءة فعلية للمستودع المعتمد، وأحدث التزامات الفرع الافتراضي والفروع وتشغيلات GitHub Actions، مع وقت آخر فحص وحالة أي بيانات محفوظة قديمة. عند بلوغ حد REST، يستطيع المستودع العام عرض التزاماته من موجز GitHub العام، مع تمييز المصدر وعدم إظهار بيانات الفروع أو البناء أو تواريخ الرفع كأنها متاحة. تُحدّث ذاكرة D1 المؤقتة بعد خمس دقائق، ويمكن طلب تحديث يدوي بفاصل دقيقة، مع احترام موعد تجدد حد REST. لا تُشغّل اللوحة بناءً أو تكتب إلى GitHub.

تبدأ قاعدة جديدة بملفات تعريف للوكلاء ومساحات أولية؛ لا تتضمن مهامًا أو نشاطًا أو نتائج متجر مصطنعة. هذه الملفات تحدد تخصصات العمل، ولا تعني أن وكلاء ذكاء اصطناعي يعملون بالفعل.

عند فتح النسخة الحية من متصفح يحتوي النسخة المحلية القديمة، يُنقل العمل المضاف يدويًا فقط إلى قاعدة حية جديدة ما زالت في المراجعة `0`، بعد التحقق منه. تُستبعد مهام ونشاط العرض الأولي، وتبقى النسخة القديمة في المتصفح دون حذف. لا يُدمج هذا النقل تلقائيًا مع بيانات خادم سبق تعديلها.

## الوصول والتكامل

الموقع المنشور خاص، ويعتمد وصول المتصفح إلى API على هوية ChatGPT المرسلة بواسطة Sites. هذه النسخة مساحة مشتركة لمؤسسة واحدة؛ لا تتضمن نظام حسابات مستقلًا أو أدوارًا أو عزلًا بين مؤسسات متعددة. أسرار الخدمة في بيئة الخادم ولا تُضمّن في المصدر أو تصدير بيانات العمل. يستطيع مالك الموقع تنزيل ملف اتصال خاص من شاشة الربط لعميل AAS؛ يحتوي وصول الخدمة والموقع الخاص. مسودة Android تدعم استيراده وحفظه مشفرًا باستخدام Android Keystore، وتحتاج نشر نسخة مرجعية قبل استخدامها على جهاز. احذف ملف الاتصال بعد الاستيراد ولا تشاركه.

المستودع المرتبط هو [Mohammadzxzx1991/Mohammad-Ahmed-Ghannam](https://github.com/Mohammadzxzx1991/Mohammad-Ahmed-Ghannam) الذي حدده المستخدم. شاشة «مستودع GitHub» تراقب المصدر المنشور وحالة Actions عند توفر REST، أو تعرض الالتزامات من الموجز العام مع قيوده بوضوح؛ ربط المصدر لا يثبت اتصال تطبيق مثبت أو نجاح بناء غير موجود. قراءة المستودع العام لا تشترط رمزًا، لكن قد تتأثر بحدود الشبكة المشتركة. يمكن إعداد `GITHUB_TOKEN` في بيئة الخادم لرفع حد REST، دون حفظه في ملفات المشروع.

نسخة العمل المحلية في `/workspace/apps/mohammad-ahmed-ghannam` على الفرع `aas/live-command-center`، من الأصل `aa1db27385700f30773db27d81898741ad698a04`. تعديلات Android المبدئية بقيت محلية وغير منشورة بسبب اختلاف هوية وصور تطبيق Luqta عن المصدر المنشور الذي جرى فحصه. لم تُدفع تعديلات إلى هذا المستودع ولم يُعلن إنشاء PR أو APK. المعرف `01a13140-17e0-7168-9a28-f71e37190060` لا يتيح الوصول إلى تغييرات غير منشورة في جلسة Codex الأخرى.

الربط المنجز هنا هو متابعة المصدر والبناء في GitHub وتشغيل API اللوحة وقاعدتها. اتصال جهاز Android يحتاج توحيد مصدر التطبيق المقصود ثم بناء نسخة تتضمن عميل AAS وتثبيتها وتهيئة وصول المالك واستلام إيصال مزامنة. نتائج البناء والفحص المتاحة موثقة في سجل التحقق. أُضيف مسار خادمي لتوليد النص وتحليل الصور عبر Gemini، ويحتاج إعداد مفتاح وموديل في بيئة الخادم؛ عند غيابها يعيد خطأ واضحًا دون نتيجة مصطنعة. لا يوجد تنفيذ مستقل للوكلاء. مقارنة المنتج تعيد سعره المسجل في المتجر فقط؛ خدمات مقارنة المنافسين والرادار والبيانات الاجتماعية تُرجع خطأ عدم تهيئة حتى توصيل مزود حقيقي.

راجع [عقد API](docs/api.md)، و[دليل الربط](docs/integration.md)، و[المعمارية الحالية](docs/architecture.md)، و[خارطة التنفيذ](docs/roadmap.md).

منفّذ Node الاختياري يدعم GitHub Actions أو جهازًا داخل الشبكة المحلية باتصال صادر إلى اللوحة، ويطبق رقعًا يراجعها المشغّل ويشغّل أوامر اختبارات محددة ويعيد نتائج فعلية. لا يولد تعديلات بذكاء اصطناعي، ولا يدفع تغييرات إلى المستودع تلقائيًا. إعدادات وصوله مستقلة عن مفتاح تطبيق Android، وتنزّل من جلسة المالك فقط. يتطلب تفعيل Actions تثبيت ملف التشغيل وإعداد أسراره، ويتطلب الخادم المحلي تشغيل المنفّذ داخله. راجع [إعداد المنفّذ](docs/runner-setup.md).

## خطوات التفعيل

1. افتح [المستشار](https://amer-ai-command-center.eagerlark64.chatgpt.site/#advisor)، ثم «فحص وربط Gemini». افتح [صفحة مفاتيح Gemini](https://aistudio.google.com/apikey) واستخدم زر نسخ **قيمة المفتاح الفعلية**؛ اسم المفتاح مثل «Gemini-API-2» ورقم المشروع ليسا مفاتيح وصول. الصق القيمة في حقل كلمة المرور فقط، دون إرسالها في المحادثة.
2. اضغط «جلب النماذج من مفتاحي». تُجلب القائمة من Google وتُستبعد النماذج التي لا تدعم توليد المحتوى؛ لا توجد أسماء مُفترضة أو خانة اسم نموذج يدوي. إذا كان المزوّد مهيّأ، تستطيع اختيار استخدام المفتاح المحفوظ بدل إدخاله مجددًا.
3. اختر نموذجًا من القائمة، ثم اضغط «حفظ النموذج وربط المساعد». يحتفظ الخادم بالمفتاح مشفرًا خلال جلسة اختيار مدتها عشر دقائق، فلا يُرسل المفتاح مرة ثانية. جلب القائمة لا يغيّر الإعداد الحالي؛ يتم اعتماد الإعداد بعد التحقق من النموذج وحفظه. عند انتهاء الجلسة أعد جلب القائمة. تُستبدل جلسة الفحص السابقة بفحص جديد.
4. بعد نجاح الحفظ أرسل في المحادثة: «لخّص حالة المهام واقترح خطوة تالية دون تنفيذها». تحقق من ظهور Gemini واسم النموذج كمصدر للرد. جلب النماذج وفحص بياناتها لا يثبتان نجاح توليد فعلي أو توفر حصة استخدام. التوصيات الموسومة بالمستشار المحلي لا تمثل ردًا من نموذج، وتطبيق أي مقترح يحتاج اعتمادك.

تبقى أخطاء المفتاح والصلاحيات والحفظ داخل نافذة الإعداد. يقبل الخادم المفتاح الخام أو النص المنسوخ بصيغة متغير بيئة أو بين علامتي اقتباس. لا يُقبل اسم مفتاح بديلًا عن قيمته. يظل مسار الإعداد السابق متوافقًا مع عملاء API الموجودين.

لربط البيانات، افتح [قاعدة البيانات](https://amer-ai-command-center.eagerlark64.chatgpt.site/#database)، واتبع [دليل جسر SQLite](docs/database-bridge.md). يتطلب الجسر Node.js 24 وملف SQLite فعليًا، وتشغيله على جهاز يستطيع الوصول إلى ذلك الملف والخادم المقصود. عنوان خادم ويب وحده لا يحدد ملف القاعدة، وتحتاج الشبكة المحلية إلى وصول متاح من جهاز الجسر.

تظل الوصلة في حالة انتظار حتى يصل اتصال ولقطة فعلية من الجسر. لا يُعد إنشاء الوصلة أو إدراج عملية في الطابور إثباتًا لاتصال الخادم المحلي أو تطبيق التغيير؛ راجع آخر استلام وإيصال العملية.
