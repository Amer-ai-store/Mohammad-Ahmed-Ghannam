# خدمة أمان الخاصة للسجلات

واجهة GitHub Pages تعرض السجلات من هذه الخدمة عبر HTTPS. الصفحة العامة لا تحتوي رموز وصول أو سجلات فعلية. تبقى قاعدة SQLite والرموز على **مضيف إدارة موثوق منفصل**. تجهيز هذه الملفات لا يعني أن الخدمة ثُبّتت أو أن مراقبة فعلية بدأت.

```text
جامع معتمد على الخادم ── HTTPS + رمز كتابة ──> خدمة أمان الخاصة
متصفح لوحة GitHub Pages ── HTTPS + رمز قراءة ──> خدمة أمان الخاصة
```

الخدمة تستخدم مكتبة Python 3 القياسية؛ لا تحتاج `pip`. تقرأ سجلات موحّدة يرسلها جامع معتمد، ولا تنفّذ أوامر من الأحداث. جامع SSH المرفق سابقًا مخصص لـ **Linux فقط**؛ لم يُجهّز جامع Windows هنا. ربط أحداث Windows يتطلب موصلًا معتمدًا لاحقًا يحوّل السجلات المصرّح بها إلى العقد أدناه.

**لا تثبّت هذه الخدمة على خادم الإنتاج Windows المسمى `JAWAFFASVR`، ولا تفتح عليه منافذ واردة، ولا تعدّل عامل RSA الحالي الذي يعمل باتصالات صادرة فقط.** شغّل الخدمة على مضيف الإدارة المنفصل، خلف وكيل HTTPS موثوق موجود أو يهيئه مسؤول المضيف بصورة مستقلة. هذه الملفات لا تثبّت شهادة أو وكيلًا، ولا تغيّر جدارًا ناريًا.

## الرموز والاتصال

اضبط المتغيرات التالية عبر مدير أسرار موثوق:

| المتغير | الغرض |
| --- | --- |
| `AMAN_READ_TOKEN` | رمز مستقل لقراءة السجلات من اللوحة والبحث الجغرافي الاختياري. |
| `AMAN_COLLECTOR_TOKEN` | رمز مختلف لإضافة الأحداث والنبضات فقط؛ لا يمنح قراءة السجلات. |
| `AMAN_ALLOWED_ORIGIN` | الأصل المسموح للمتصفح: `https://amer-ai-store.github.io`، دون مسار المستودع أو شرطة أخيرة. |

ولّد رمزين عشوائيين مستقلين بمدير كلمات المرور؛ يشترط كل منهما من 32 إلى 512 محرفًا من الحروف والأرقام اللاتينية والرموز `-` و`_` و`.` و`~`. لا تستخدم كلمة مرور حسابك أو مفتاح OpenAI. لا تضع قيمة أي رمز في سطر أوامر أو مستودع GitHub أو عنوان URL أو محادثة أو لقطة شاشة. لا تطبع بيئة العملية، واحمِ وصول مستخدمي المضيف إلى الخدمة وملف القاعدة.

في المتصفح، أدخل **رابط API الكامل عبر HTTPS** ورمز القراءة داخل لوحة أمان. يحتفظ المتصفح بالرمز في الذاكرة أثناء فتح الصفحة؛ إعادة التحميل تمسحه. لا تُدخل رمز الجامع في اللوحة. يحتاج API شهادة HTTPS يثق بها المتصفح؛ عنوان HTTP أو شهادة محلية غير موثوقة لن يصلحا لاتصال صفحة GitHub Pages الآمنة.

## تشغيل يدوي على مضيف الإدارة

ابدأ بالفحص دون تشغيل خدمة أو قراءة سجلات حقيقية:

```sh
python3 monitor_server.py --help
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

أنشئ مجلدًا خاصًا لقاعدة SQLite خارج ملفات الويب ومستودع المصدر، بصلاحية `0700` للمجلد و`0600` لملف القاعدة المملوكين لمستخدم الخدمة نفسه، واضبط مساره في الأمر التالي. ترفض الخدمة الروابط الرمزية والصلبة للقاعدة، وتحتفظ SQLite بملفاتها المرافقة المؤقتة داخل المجلد الخاص نفسه. بعد ضبط الرمزين مسبقًا في بيئة العملية بصورة آمنة:

```sh
python3 monitor_server.py --db /PRIVATE/PATH/aman.sqlite3
```

الربط الافتراضي `127.0.0.1:8765`. أبقه كذلك عند وضع وكيل HTTPS على المضيف نفسه، ووجّه الوكيل إلى هذا العنوان محليًا. لا تنشر قاعدة SQLite أو ملفاتها المرافقة، ولا تمرّر الأسرار ضمن إعدادات عامة.

للتشغيل التفاعلي دون وضع الرموز في الأمر أو سجل الصدفة، يمكن إدخالهما من مدير كلمات المرور عبر مطالبتين مخفيتين. عدّل مسار القاعدة فقط؛ لا تضف قيم رموز إلى النص:

```sh
python3 - <<'PY'
import getpass
import os
import runpy
import sys
import warnings

warnings.simplefilter('error', getpass.GetPassWarning)
os.environ['AMAN_READ_TOKEN'] = getpass.getpass('Read token: ')
os.environ['AMAN_COLLECTOR_TOKEN'] = getpass.getpass('Collector token: ')
os.environ['AMAN_ALLOWED_ORIGIN'] = 'https://amer-ai-store.github.io'
sys.argv = ['monitor_server.py', '--db', '/PRIVATE/PATH/aman.sqlite3']
runpy.run_path('monitor_server.py', run_name='__main__')
PY
```

يتوقف هذا المثال إذا تعذّر الإدخال المخفي. للتشغيل الدائم، اجعل مسؤول مضيف الإدارة يربط الخدمة بمدير الأسرار وآلية الخدمات المناسبة، مع وصول محدود لملف القاعدة. تغيير الرمزين يتطلب تحديث بيئة الخدمة وإعادة تشغيلها؛ حدّث اللوحة أو الجامع المعني بعدها.

## المسارات والصلاحيات

تُرسل الرموز في ترويسة `Authorization: Bearer` فقط. لا تستخدم الخدمة ملفات تعريف ارتباط، ولا يحتاج طلب المتصفح إلى `credentials: include`.

| الطلب | الصلاحية |
| --- | --- |
| `GET /api/events` | رمز القراءة؛ يعيد `events` و`sources` و`server_time`. |
| `POST /api/ingest` | رمز الجامع؛ يقبل JSON حتى 256KiB و100 حدث في الدفعة، أو قائمة فارغة كنبضة. |
| `GET /api/geo?ip=...` | رمز القراءة؛ بحث اختياري تقريبي عن IPv4 عام صالح. |
| `OPTIONS` | فحص CORS بلا سجلات أو أسرار؛ يسمح بالأصل المضبوط وترويسة Authorization فقط حسب الطلب المدعوم. |

يرفض API أصل متصفح مختلفًا. CORS لا يحل محل المصادقة: كل طلب سجلات أو استقبال يحتاج الرمز الصحيح، حتى خارج المتصفح. يفصل رمز الكتابة عن رمز القراءة لتقليل صلاحيات الجامع.

الاحتفاظ محدود بأحدث **150 حدثًا** أو **آخر 7 أيام** أو حد حالة **180KiB**، أيها يفرض الحد الأقل، وبحد أقصى **25 مصدرًا**. تُحذف الأحداث القديمة عند القراءة أو الاستقبال؛ لا توجد مهمة حذف مجدولة أثناء توقف الخدمة. عند تجاوز 25 مصدرًا، تُزال المصادر الأقدم وأحداثها من هذه اللوحة. اللوحة ليست أرشيف تدقيق كاملًا؛ احتفظ بالسجلات الأصلية على مصادرها وفق احتياجك. إعادة إرسال الحدث بمعرّفه الثابت للمصدر نفسه لا تنشئ نسخة أخرى. لا يحذف الجامع حدثًا من طابوره إلا بعد استجابة ناجحة تتضمن `{"ok":true}`.

## ربط جامع Linux

جامع SSH السابق يستخدم `AMAN_COLLECTOR_TOKEN` نفسه من البيئة، مع **الرابط الكامل لمسار الاستقبال**:

```sh
python3 collector.py \
  --endpoint https://YOUR-MANAGEMENT-API/api/ingest \
  --source-id my-linux-server \
  --spool /PRIVATE/PATH/spool.sqlite3
```

استبدل النطاق والمسار الخاصين بك فقط. لا تفترض أن نطاق GitHub Pages هو API، ولا تغيّر نظام إنتاج Windows كي يعمل جامع Linux. يجب أن يسمح مصدر السجلات باتصال HTTPS صادر إلى مضيف الإدارة؛ أي تغيير للشبكة يُراجع ويُنفّذ بصورة مستقلة عند الحاجة.

مثال عقد بأحداث اصطناعية؛ عنوان IP مخصص للتوثيق:

```json
{
  "source_id": "my-linux-server",
  "events": [
    {
      "id": "stable-event-id",
      "source_id": "my-linux-server",
      "session_id": "sshd-session-id",
      "occurred_at": "2026-10-29T12:00:00.000Z",
      "type": "login_success",
      "actor": "admin",
      "ip": "203.0.113.10",
      "action": "SSH login accepted",
      "metadata": {"service": "sshd"}
    }
  ]
}
```

الأنواع المدعومة: `login_success` و`login_failed` و`logout` و`http_request` و`process`. النوعان الأخيران يتطلبان مصدر سجلات مناسبًا؛ وجودهما في العقد لا يعني تفعيل جمعهما. يسجل حدث `process` فعلًا ورد في مصدر تدقيق مصرح به، ولا يشغّل أي عملية. قد يكون `ip` بقيمة `null` عند غيابه من السجل. معرّف الجلسة قرينة لربط الأحداث المسجلة؛ لا يضمن تتبعًا كاملًا أو هوية الشخص.

## الموقع الجغرافي وحساب ChatGPT

البحث الجغرافي لا يعمل تلقائيًا. عند طلبه صراحةً، ترسل الخدمة عنوان IP العام فقط إلى `ipapi.co` عبر عنوان HTTPS ثابت، دون رموز الوصول. المهلة 5 ثوانٍ وحد الاستجابة 64KiB. الموقع مدينة/منطقة تقريبية، ويمكن فتح إحداثياتها في خرائط Google بإجراء مستقل. لا يكشف IP عنوان المنزل، ولا يضمن كشف المصدر خلف VPN أو Tor أو NAT، ولا يثبت هوية شخص.

هذه الخدمة لا تصل إلى سجل دخول حساب ChatGPT الشخصي أو جلساته. راجع إعدادات أمان ChatGPT مباشرةً؛ ربط أي مصدر مؤسسي يتطلب واجهة رسمية وصلاحيات مستقلة لم تُجهّز هنا.

## فحص الأعطال

- `401`: تأكد من استخدام رمز القراءة في اللوحة ورمز الجامع في الجامع، دون طباعتهما.
- خطأ CORS: تأكد أن الأصل هو `https://amer-ai-store.github.io` تمامًا؛ مسار المستودع جزء من رابط الصفحة وليس الأصل.
- خطأ اتصال: راجع شهادة HTTPS وتوجيه وكيل مضيف الإدارة إلى `127.0.0.1:8765`. لا تفتح منافذ على `JAWAFFASVR` لمعالجة هذا الخطأ.
- عدم ظهور أحداث: تحقق من مصدر السجل والجامع ونبضاته. لا تعرض اللوحة بيانات حقيقية قبل ربط مصدر يعمل.
- الموقع غير متاح: قد لا يكون العنوان IPv4 عامًا أو قد تفشل خدمة تحديد الموقع؛ السجلات نفسها مستقلة عن البحث الجغرافي.

لا تسجّل محتوى الترويسات أو الأجسام في الوكيل أو الخدمة. تتضمن السجلات الأمنية أسماء حسابات وعناوين IP؛ اجعل قاعدة SQLite ونسخها الاحتياطية خاصة بمدير النظام.
